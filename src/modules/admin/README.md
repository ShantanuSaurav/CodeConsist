# modules/admin

**Owns:** the administrator console at `/admin`: a separate sign-in (Admin User ID + password, never a learner account), the admin session token (`STORAGE_KEYS.adminToken`), and the pages for users, language tracks, stages, challenges, analytics, the audit log, the optional Microsoft Excel mirror and credential changes.

**Public API (`index.ts`):** `AdminApp` - the whole `/admin/*` route tree with its own `AdminAuthProvider`. The app mounts it lazily, so learners never download it.

**Talks to:** `/api/admin-auth/*` and `/api/admin/*` only (`services/adminApi.ts`). Every one of those routes is independently gated server-side by `requireAdminAuth` (`server/admin-auth.js`), which verifies the bearer token against the live admin record on every request. This module could be deleted and a learner's token would still get a 401 from all of them.

**Three states of question.** *Authored* ones live in `src/modules/challenges/content` and go through `npm run check` (which executes every solution). *Edited here* (`modified: true`) is an authored id whose full replacement was saved from the console: the server stores it in `customChallenges` in `server/data/db.json` under the same id, learners see the replacement in the authored position (so it keeps its stage - the server refuses a stage move), and the row's "Put the original back" (`POST /content/challenges/:id/revert`) deletes the replacement again. *Written here* (`custom: true`) is a question whose id is not in the authored bank at all - created with the "New question" wizard, appended after the authored lessons of its stage, and deletable outright. All three are edited with the same wizard (`components/QuestionWizard.tsx`: type first, then a per-type form with every field - options, blanks, steps, test cases, and worked examples for a stage test); the server (`server/custom-challenges.js` + the zod `ChallengeSchema` compiled at boot) validates every save, executes a coding question's solution against its test cases (and checks a `debug` starter fails), holds a stage test to its shape, and keeps an authored question's Learn-mode `concept` untouched. Removing a question from a stage (a reversible hide) works on all three and is a `contentOverrides` entry in the same db.json, merged by `server/content.js`.

**AI question assistant.** The "AI new question" button on the Challenges page opens `components/AiQuestionAssistant.tsx`: the admin picks a type, describes the question in plain words, and Gemini writes it out in full, names the stage it fits best (with a confidence and alternatives), and compares it with every question already in the bank - each overlapping one is labelled duplicate / similar / distinct and the verdict (push it / push with care / don't push) is computed from those labels, so a duplicate can never be saved from the assistant. A second tab asks Gemini for new question ideas for a stage, each marked New or Overlaps "<title>"; "Write this one" feeds an idea straight back into the first tab. Everything talks to `/api/admin/ai/*` (`server/ai.js`, `server/ai-questions.js`): the `GEMINI_API_KEY` is read only by the API server and is never bundled or sent to the browser, and what goes to Google is the admin's own words plus the titles and prompts of existing questions for the duplicate check - never learner data or credentials. Every AI draft still goes through the same validation and solution execution as the wizard (`validateQuestion` before it is shown, and the normal create route when it is saved); "Review in wizard" opens it in `QuestionWizard` (its `draft` prop) for edits by hand. With no key set, the drawer explains what to add to `.env` and stays switched off; the Dashboard's Integrations card shows the same status.

**Does not own:** learner progress, grading, XP (`platform/session`, `server/index.js`).
